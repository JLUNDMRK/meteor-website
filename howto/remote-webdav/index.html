Remote WebDAV

Advanced path for streaming from home while you are away. Skip this if Download / offline playback is enough.

Suggested sequence

  1. Confirm local WebDAV works in Meteor.
  2. Use HTTPS with a certificate your device can trust.
  3. Give the NAS a stable hostname (DDNS or your own domain) if your public IP changes.
  4. Confirm you have a usable public IPv4 path (see below).
  5. Add a port-forward (or equivalent) from the router to the NAS WebDAV HTTPS port.
  6. Test from outside the home network (mobile data, Wi‑Fi off).

A home VPN (so your phone joins the LAN) is often safer than publishing WebDAV. Meteor does not create that VPN for you — use your router/NAS vendor’s VPN, or another VPN you trust.

HTTPS and certificates

  • Prefer HTTPS for anything reachable from the Internet.
  • Use a certificate that matches the hostname you type in Meteor (for example Let’s Encrypt via your NAS).
  • Self-signed certificates may work at home but often fail or warn on mobile clients over the Internet.
  • Use a strong, unique password — and ideally a dedicated user with read-only access to movie folders.

Stable hostname / DDNS

Many home connections get a changing public IP. A DDNS hostname updates DNS when the IP changes, so Meteor can keep using the same URL.

  • Synology: Control Panel → External Access → DDNS (vendor hostname such as synology.me, or another provider).
  • Other NAS brands: look for DDNS, Dynamic DNS, or “Easy Connect”-style hostnames — then confirm that hostname works with WebDAV, not only with the vendor’s own apps.

Synology notes

QuickConnect and DDNS are different. QuickConnect helps Synology apps reach DSM through Synology’s service and does not replace a normal WebDAV URL. Synology documents that WebDAV should use a direct IP or DDNS hostname — not a QuickConnect address.

Comparison: QuickConnect vs DDNS. WebDAV access: Access files with WebDAV. Connection issues (including QuickConnect and ports): Resolve WebDAV connection issues.

Typical HTTPS WebDAV port on Synology is 5006 unless you changed it — forward that (or your reverse-proxy HTTPS port) to the NAS.

Port forwarding examples

Port forwarding (also called Port Mapping, Virtual Server, or NAT rules) tells the router: “traffic arriving on this public port goes to this device and port on my home network.”

You usually need:

  • The NAS/PC local IP (give it a DHCP reservation so it does not change).
  • The WebDAV HTTPS port on that device.
  • TCP protocol (unless your vendor says otherwise).
ASUS
  1. Open the router admin page (often http://www.asusrouter.com).
  2. Go to WAN → Virtual Server / Port Forwarding.
  3. Enable port forwarding, add a profile: external port → NAS local IP → internal WebDAV HTTPS port, TCP.

Official FAQ: ASUS — Virtual Server / Port Forwarding.

TP-Link
  1. Log in to the router admin page.
  2. Look under Forwarding → Virtual Servers, or Advanced → NAT Forwarding → Virtual Servers / Port Forwarding (wording depends on the model).
  3. Add the external port, internal IP, internal port, and protocol.

Official overview: TP-Link — port forwarding.

Netgear / other routers

Search for your model plus port forwarding. Menus may say Port Forwarding, Port Mapping, Virtual Server, or NAT / Firewall rules.

Example starting point for many Netgear models: the router’s Advanced → Port Forwarding / Port Triggering section in the vendor help for your exact model.

Public IP, NAT, and CGNAT

Port forwarding only works if the Internet can reach your router’s public address. A practical check:

  1. Note the router’s WAN IPv4 address in the router status page.
  2. On a phone or PC, open a “what is my IP” site and note the external IPv4 you see.
  • Same address — your router likely has the public IPv4 (good starting point for forwarding).
  • Different addresses — there is another NAT layer in front of you. That might be CGNAT, double NAT (ISP router + your router), or another intermediate network. Different addresses do not automatically mean CGNAT.
  • WAN address in 100.64.0.0/10 — shared address space often used for CGNAT.
  • WAN address in private ranges (10.x, 172.16–31.x, 192.168.x) — your router is behind another NAT device.

If inbound connections fail after correct forwarding, ask your ISP whether you are on CGNAT and whether a public IPv4 (or an alternative) is available. A VPN into home can still work when inbound ports do not.

Test from outside

  1. Turn off home Wi‑Fi on the phone; use mobile data.
  2. In Meteor, use the HTTPS WebDAV URL with your hostname/DDNS and forwarded port.
  3. If it fails only off-LAN while local IP still works, revisit forwarding, firewall, DDNS IP, and the NAT checks above.

Some routers lack NAT loopback / hairpin: a DDNS name may fail while you are inside the home network even when it works from mobile data. Test from outside to avoid false failures.
